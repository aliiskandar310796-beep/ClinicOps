ClinicOps Integrity Gate

A pre-release evidence-reconciliation and change-propagation screen for supplied medical-device regulatory information. It checks declared controlled sources against declared downstream surfaces, preserves source traceability, and routes ambiguity to human RA/QA review.

Boundary: Integrity Gate is an evidence-control workflow, not a legal, regulatory or compliance determination. A machine result never replaces RA/QA judgement.

The operational question

When a regulated fact changes, the hard question is often not whether one document changed. It is whether the approved information still agrees across every client-declared surface that is supposed to carry it.

Integrity Gate turns that into a repeatable evidence check:

  1. load client-approved controlled sources and declared downstream surfaces;
  2. reconcile declared fields only where one supplied authoritative value exists;
  3. refuse to infer authority when supplied controlled sources disagree;
  4. check declared approved changes against the surfaces the client identifies as affected;
  5. package every discrepancy with evidence references;
  6. require named human review before external release.

Four fail-closed states

PASS

No discrepancy found by the declared automated checks. Human review is still required for external release.

REVIEW_REQUIRED

A supplied field is missing or differs from the single supplied controlled value.

UNRESOLVED_AUTHORITY

The supplied controlled evidence does not establish one authoritative value. ClinicOps does not guess.

HOLD_FOR_HUMAN_DECISION

A declared change has not propagated, its approved source does not match the declared new value, or a downstream surface contains a conflicting value.

What is already executable

  • deterministic JSON input validation;
  • cross-surface field reconciliation;
  • unresolved-authority detection;
  • declared change-propagation checks;
  • JSON, Markdown and HTML evidence bundles;
  • SHA-256 manifest binding and tamper detection;
  • fail-closed human-review preparation and approval gate;
  • final verification of the exact case, bundle and review state.

What is not yet proven

Software validation is separate from market validation. ClinicOps will not call Integrity Gate commercially validated until real buyer conversations show repeated pain and at least one concrete commercial commitment under the existing validation rules.

The first live pilot should therefore stay bounded: one device family or Basic UDI-DI group, a small number of supplied controlled sources and downstream surfaces, explicit fields, explicit change expectations, and one qualified human reviewer.
