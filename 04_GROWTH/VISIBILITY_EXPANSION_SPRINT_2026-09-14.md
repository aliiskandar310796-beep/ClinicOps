# ClinicOps Visibility + Expansion Sprint — 2026-09-14

Status: internal execution asset. Buyer/prospect identities and private communication evidence stay outside the public repository.

## Objective

Turn the current product surface into qualified buyer movement quickly without confusing activity with validation.

The sequence is:

`discoverability -> useful proof -> qualified account -> verified route -> bounded outreach -> buyer response -> repeated pain -> priced scope -> activated work -> expansion`

## Current observation

As observed through connected Search Console tooling on 2026-09-14:

- canonical sitemap: 23 URLs;
- only the homepage currently shows as indexed in the URL tracker;
- 13 URLs were `not_indexed` with `URL is unknown to Google`;
- 9 URLs remained pending inspection;

This is a distribution problem before it is a content-volume problem.

Do **not** respond by mass-producing thin pages.

## Sprint priorities

### P0 — make discovery measurable

1. Keep the canonical sitemap registered in GSC Wizard.
2. Track all sitemap URLs in the indexing tracker.
3. Inspect newly deployed / strategically important URLs after meaningful releases, not continuously.
4. Record whether a page is unknown, discovered, crawled, indexed or receiving impressions; do not collapse those states into one metric.
5. Submit the canonical sitemap in Google Search Console UI when a browser-capable operator is available.
6. Add Bing / IndexNow only after its key and key-file verification are correctly configured; never report `202 accepted` as confirmed indexing.

### P1 — distribute proof, not generic promotion

Every distribution touch should point to one useful proof object:

- free Regulatory Change Integrity Check;
- synthetic specimen register;
- Transition Map sample;
- workload/economics calculator;
- SS(C)P public-record research;
- one tightly scoped buyer question.

Default CTA hierarchy:

`use proof -> inspect method -> scope one real workflow`

### P2 — run the 33-cell acquisition model as bounded experiments

The 33 cells in `sales/global-sales-swarm.json` are opportunity lanes, not blast identities.

For each active cell:

- qualify three net-new accounts or routes;
- check HubSpot + Gmail Sent + Outlook Sent + private outreach master before outreach;
- suppress previous contact unless an approved follow-up path exists;
- verify the route;
- use one operational question;
- record delivery separately from buyer response;
- kill or redesign cells that repeatedly deliver without buyer movement.

Company-wide send ceiling remains 15 outbound emails/day.

### P3 — prioritize higher-leverage distribution

Order of operations:

1. qualified partner routes with existing RA/QA audiences;
2. professional communities / education / events;
3. targeted manufacturer outreach with a specific evidence-backed workflow hypothesis;
4. durable directory / marketplace presence;
5. broad social posting only when it reuses validated proof.

One partner that repeatedly exposes ClinicOps to relevant buyers is worth more than a large number of unqualified impressions.

## Outreach quality contract

Every outbound draft must pass all of these:

- account is net-new or follow-up is explicitly justified;
- legal/jurisdiction route is appropriate;
- no Danish-domiciled cold email;
- no permanent suppression match;
- no fear-based regulatory urgency;
- no unsupported compliance or EUDAMED-coverage claim;
- one buyer/workflow hypothesis only;
- one proof link maximum unless the recipient asks for more;
- one low-friction question;
- an easy opt-out / no-reply-needed path when appropriate.

Bad outreach:

> We use AI to automate compliance across EUDAMED and MDR. Can we schedule a demo?

Better pattern:

> When one approved regulated value changes, how does your team verify that the RIM/master record, EU-facing data and controlled documents all moved together? We built a small human-reviewed reconciliation workflow for exactly that handoff. If this is a repeated problem for your team, I can show the specimen or scope one real change event.

The second pattern asks about work; it does not manufacture a compliance conclusion.

## Visibility content loop

For each validated research or product signal:

`primary evidence -> bounded observation -> useful public artifact -> short distribution derivative -> buyer question -> response -> commercial learning`

Create derivatives only when they add a new distribution surface or buyer framing. Do not create five versions merely to increase post count.

## Search / GEO doctrine

Priorities:

1. crawlable, answer-first HTML;
2. clear canonical URLs;
3. internal links from strong pages to proof / conversion pages;
4. structured data where it accurately describes the page;
5. external references / links earned through useful research and partnerships;
6. optional machine-orientation files only when cheap and honest.

`llms.txt` is an optional experiment, not an SEO claim. Do not describe it as a ranking factor or evidence of AI visibility.

## Expansion beyond the initial offer

ClinicOps can explore adjacent work aggressively, but the gateway remains:

`DISCOVER -> TEST -> SELL MANUALLY -> PROVE REPEATABILITY -> AUTOMATE`

Promising adjacent wedges include workflows with the same primitives:

- controlled-document change propagation;
- UDI / master-data reconciliation;
- authorised-representative portfolio evidence control;
- regulatory intelligence change detection;
- post-market / vigilance evidence reconciliation;
- supplier / translation / artwork controlled-change operations;
- expert-service evidence packs outside medical devices where review is expensive and authority must remain human-controlled.

No adjacent wedge becomes a product line because it is technically buildable. It earns expansion through E4-E9 evidence.

## Daily control tower

Track these numbers, in this order:

1. net-new qualified accounts/routes;
2. duplicate / prohibited accounts suppressed;
3. verified demand tests delivered;
4. human buyer responses (E4);
5. repeated pain confirmations (E5);
6. priced scope / procurement / budget-owner movement (E6);
7. commercial activation (E7);
8. accepted delivery/payment (E8);
9. repeat/expansion/referral (E9);
10. pages newly discovered/crawled/indexed and non-branded search impressions.

Generated drafts, page count, agent actions and impressions without buyer movement are diagnostics, not wins.

## Kill criteria

Change the channel, buyer, offer or message when:

- a cell repeatedly reaches verified inboxes but produces no useful response;
- a page is indexed yet generates no relevant query impressions over a meaningful observation window;
- buyers engage with research but will not discuss a real workflow;
- ten qualified buyer conversations still produce no concrete willingness to sponsor a pilot or priced scope.

The goal is not maximum activity. It is fast information gain followed by concentrated execution where evidence improves.
