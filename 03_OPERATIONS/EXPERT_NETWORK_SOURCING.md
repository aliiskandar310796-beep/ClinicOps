# Expert Network Sourcing and Coverage Plan

Status: EXECUTION PLAYBOOK

## Priority order

Build coverage from actual commercial pain, not from a desire to list many specialties.

### P0 — Denmark / core MedTech

Source two or more credible options where feasible for:

- MDR / IVDR regulatory affairs;
- EUDAMED / UDI / data operations;
- Danish medical-device language / local-market review;
- Danish pharmacovigilance / medical information;
- clinical evidence / PMS / PMCF.

### P1 — Nordic country nodes

Test buyer demand first, then source for:

- Sweden;
- Norway;
- Finland;
- Iceland where commercially justified.

Do not claim a Nordic node until at least one person is verified and assignment-ready.

### P1 — high-value technical specialties

Build on demand for:

- IVD;
- SaMD / software;
- human factors / usability;
- medical-device cybersecurity;
- biostatistics / clinical methods;
- specialist physician/nurse review.

## Sourcing channels

Prefer targeted sourcing and referrals:

1. known professional network / warm introductions;
2. regulatory consultancies and specialist subcontractors;
3. LinkedIn / Apollo professional discovery;
4. professional associations and country-specific societies;
5. specialist LSP / medical-language networks;
6. client/partner referrals where conflicts allow.

Do not scrape or publish a public roster.

## Screening funnel

```text
identified
→ relevance screen
→ introductory call
→ credentials/scope check
→ conflict/independence screen
→ commercial/contract readiness
→ VERIFIED
→ AVAILABLE or LIMITED
→ assignment-specific gate
```

## Discovery call

Confirm:

- actual work they do;
- evidence of experience;
- jurisdictions;
- languages;
- tasks they will and will not perform;
- whether they can subcontract;
- current capacity;
- turnaround expectations;
- preferred commercial structure;
- conflicts;
- insurance where relevant;
- data-handling limits;
- whether they consent to any public wording.

Do not ask for unnecessary sensitive personal data.

## Coverage dashboard

Track privately by **capability × market**, not by total headcount.

Example cells:

- DK / MDR RA
- DK / Danish language integrity
- DK / PV
- SE / language integrity
- NO / local regulatory
- FI / local regulatory
- EU / EUDAMED/UDI
- EU / IVD
- EU / SaMD
- EU / clinical evidence

Each cell should show:

- ready experts;
- backup experts;
- status;
- latest verification;
- expected lead time;
- commercial viability;
- single-point-of-failure flag.

## Activation threshold

A capability is commercially marketable only when delivery can actually be fulfilled under ClinicOps governance.

Do not sell first and source later for a competence that is safety-, regulatory- or licence-critical.
