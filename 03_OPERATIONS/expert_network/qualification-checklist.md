# Expert qualification checklist

Use for every candidate before changing status to `AVAILABLE` or `LIMITED`.

## Identity and scope

- [ ] Preferred professional name recorded.
- [ ] Contact route confirmed.
- [ ] Country/jurisdiction recorded.
- [ ] Professional role stated accurately.
- [ ] Competency domains are specific rather than generic.
- [ ] Permitted work types defined.
- [ ] Languages separated from professional/regulatory scope.

## Credentials

- [ ] Relevant education/qualification verified from an appropriate source.
- [ ] Protected professional title/licence verified where the assignment depends on it.
- [ ] Verification source and date retained privately.
- [ ] Expiry/revalidation date captured where relevant.
- [ ] No unsupported title or authority is inferred.

## Delivery readiness

- [ ] NDA/confidentiality terms in force.
- [ ] Contract or assignment-ready framework in place.
- [ ] Payment classification/rate mechanism agreed privately.
- [ ] Insurance verified or documented as not required for the permitted work.
- [ ] Availability/status confirmed.
- [ ] Data-access boundary understood.
- [ ] Public profile consent recorded separately.

## Conflict and independence

- [ ] Current employers/clients/relationships considered for conflict.
- [ ] Assignment-specific conflict check can be performed.
- [ ] Known exclusions recorded using the minimum necessary detail.
- [ ] Independence requirements for the proposed task understood.

## Public use

- [ ] No public profile unless explicitly consented.
- [ ] Exact public wording approved.
- [ ] No employee/officer/medical-director implication without a real basis.
- [ ] No public client/project disclosure without permission.

## Assignment activation

Repeat before each engagement:

- [ ] scope;
- [ ] competence match;
- [ ] credential freshness;
- [ ] conflict check;
- [ ] confidentiality;
- [ ] contract;
- [ ] compensation;
- [ ] insurance/not-required;
- [ ] data minimisation;
- [ ] role/decision boundary;
- [ ] accountable ClinicOps owner.
