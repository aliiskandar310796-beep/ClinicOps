# ClinicOps cash-entry service ladder

Status: **internal commercial operating spec**. This file defines offer experiments and cash-linked loops. It does not change public pricing, Gumroad listings, or external regulatory claims.

## Objective

Create several ways for a qualified buyer to start small, pay for a concrete outcome, expand into repeat work, and eventually support productized / recurring revenue without speculative software development.

Revenue is never guaranteed. The system should instead make **commercially relevant actions, measurable buying signals, rapid follow-up, controlled delivery and explicit stop/change decisions** unavoidable.

The operating question is not “what else can ClinicOps sell?” It is:

> Which adjacent paid outcome can be delivered from the same evidence/reconciliation capability, has a credible buyer trigger now, and naturally ladders into repeat work?

## Default execution constraint

Until commercial evidence changes it, the **Class III Transition Map Pilot is the only default `DO NOW` service entry**. The other entries in this ladder are conditional experiments, not parallel launch instructions.

An adjacent entry may be activated only when at least one of these is true:

- a qualified buyer conversation reveals that exact narrower workflow;
- a concrete objection to the Transition Map is better solved by a smaller scope;
- a completed paid/design-partner delivery exposes a repeatable adjacent need;
- a verified external change creates a directly evidenced workflow for an existing or qualified buyer.

Do not create outreach, product surface, pricing, or delivery work for an adjacent entry merely because it exists in this document.

## Design rules

Every service entry should satisfy as many of these as possible:

1. sellable with assets already built;
2. produces a buyer-visible artifact rather than vague advice;
3. starts with a deliberately narrow scope;
4. preserves the human-review boundary;
5. has a natural repeat / expansion trigger;
6. teaches us something reusable about portfolio operations;
7. can be delivered without a new backend, portal, paid platform or large fixed cost;
8. keeps confidential buyer data out of the public repository;
9. can be stopped quickly if 3–10 qualified conversations do not produce buying evidence;
10. remains useful if one regulatory deadline passes or one market channel weakens.

Do not create new product surface merely to support an unvalidated service entry.

## Tier A — fastest active-cash entries

### A1. Portfolio Evidence Triage

**Use when:** a buyer is interested but is not ready to commission a full Transition Map and the objection is genuinely scope/commitment rather than lack of need.

**Smallest useful scope:** one manufacturer, device family or bounded record set.

**Buyer provides privately:** the portfolio extract, identifiers, certificate references and source links already available to them.

**ClinicOps produces:**
- intake-quality diagnostics;
- explicit missing / unresolved join keys;
- a compact evidence map;
- an operator work queue;
- human-reviewed notes on what should be verified next.

**Why it may create cash quickly:** lower commitment than a broader transition project while still using the existing engine.

**Expansion trigger:** more records, more manufacturers, a full Transition Map or recurring refresh.

**Stop rule:** if qualified buyers consistently want only free advice and will not sponsor even a bounded triage, do not build more triage tooling.

### A2. Class III Transition Map Pilot

This remains the core higher-value entry and should not be displaced by adjacent offers.

**Use when:** the buyer confirms repeated portfolio reconciliation / transition workload.

**Execution:** use `sales/first-pilot-scope-template.md` and the existing private bundle pipeline.

**Expansion trigger:** second manufacturer, larger portfolio, recurring update, white-label reuse or related SS(C)P / market-document operations.

### A3. Identifier + Certificate Reconciliation Sprint

**Use when:** the buyer's immediate pain is not “transition strategy” but locating and reconciling identifier / certificate evidence across a bounded portfolio.

**Deliverable:**
- normalized identifier / certificate table;
- unresolved relationships and evidence gaps;
- dated evidence references;
- prioritised operator follow-up list;
- machine-readable handoff where useful.

**Why it may sell quickly:** the buyer can test a concrete back-office workload without committing to a transformation project.

**Expansion trigger:** full Transition Map, recurring certificate/evidence monitoring or AR portfolio support.

### A4. SS(C)P Operations Readiness Pack

**Use when:** a Class III / implantable manufacturer, AR, consultancy or regulatory operator explicitly owns an SS(C)P-related operational workflow and needs a structured view of dependencies and evidence state.

**Deliverable:**
- supplied-evidence inventory;
- identifier / SS(C)P relationship checks within the evidence available;
- translation / version / evidence-control work list where relevant;
- unresolved items requiring human regulatory review;
- dated next-step plan.

Use only governed claims and limitations in `research/claims.jsonl`. Do not position this as an autonomous compliance audit.

**Expansion trigger:** recurring change control, translation operations, portfolio-wide Transition Map or white-label consultancy support.

### A5. Danish Market Document Integrity Review

**Use when:** the buyer has Danish IFU, labelling, patient/clinician-facing or other controlled device documentation and has confirmed a need for an independent integrity layer.

**Deliverable can include:**
- terminology and cross-document consistency findings;
- source-target / controlled-value checks within the agreed scope;
- documented evidence for each material finding;
- prioritised correction list;
- handoff for the buyer's responsible regulatory / quality owner.

This is a distinct cash entry that can open a broader portfolio conversation, but it must not be forced onto buyers whose need is purely portfolio regulatory operations.

**Expansion trigger:** additional document families, periodic release QA, portfolio reconciliation or consultancy subcontracting.

### A6. Change-Event Reconciliation Review

**Use when:** a buyer already has a baseline portfolio but one operational change creates new reconciliation work.

Possible triggers include a certificate update, identifier/device-family change, SS(C)P version or translation change, AR onboarding/transfer, or target-market/document-set change.

**Deliverable:** delta-focused evidence map + operator work queue rather than a full portfolio restart.

**Why it is resilient:** it can monetize recurring change rather than one deadline, where a real buyer workflow exists.

**Expansion trigger:** scheduled refreshes or Portfolio Integrity Watch.

## Tier B — recurring managed-service entries

These should initially be delivered with human oversight. Automate only repeated paid-work friction.

### B1. Portfolio Integrity Watch

**Use when:** a delivered portfolio needs periodic review because identifiers, certificate evidence, SS(C)P operations, market documents or other controlled inputs can change over time.

**Cadence:** agreed with the buyer; begin manually / semi-manually rather than building a monitoring platform.

**Output:**
- what changed since the prior review;
- what could not be verified;
- evidence references and dates;
- operator-priority follow-up queue;
- human-reviewed summary.

**Recurring cash mechanism:** the buyer pays to avoid reconstructing the portfolio state from scratch each time.

**Stop rule:** if buyers do not repeatedly value refreshes after initial delivery, do not build monitoring software.

### B2. AR / Consultancy White-Label Portfolio Desk

**Use when:** an authorised representative or consultancy has multiple manufacturer portfolios and repeated evidence-reconciliation workload.

**ClinicOps role:** invisible or co-branded back-office evidence/work-planning support that preserves the partner's legal role and client ownership.

**Possible recurring units:**
- per-manufacturer onboarding;
- per-portfolio refresh;
- monthly / quarterly batch;
- overflow support;
- transition-event support.

**Why this matters:** one partner relationship can create repeated work across multiple manufacturers without ClinicOps having to acquire every end client separately.

**Expansion trigger:** more portfolios, standing desk capacity or structured machine-readable handoffs.

### B3. Release / Document Change QA Desk

**Use when:** a manufacturer or consultancy repeatedly releases Danish-market documentation or controlled text updates.

**Output:** evidence-backed QA findings for agreed document types, with recurring release-level work rather than a one-off translation transaction.

**Recurring cash mechanism:** per release, monthly capacity block or agreed batch cadence.

**Expansion trigger:** portfolio integrity work when document changes expose wider identifier / evidence inconsistencies.

## Tier C — productized / passive and hybrid entries

These should compound distribution or monetize reusable know-how, but must not distract from active buyer validation.

### C1. Existing UDI Change-Control Matrix / digital tools

Keep the existing digital-product funnel as a low-cost passive entry. Do not change Gumroad pricing/listing without Ali's case-by-case approval.

**Role in ladder:**
- tests demand for structured regulatory-operations artifacts;
- creates a low-friction buyer relationship;
- can point qualified users toward human-reviewed portfolio work.

Template sales alone do not validate the core service offer.

### C2. Productized operator packs

Potential future assets only after recurring client work proves the format useful:
- intake templates;
- evidence-ledger templates;
- portfolio handoff schemas;
- change-event checklists;
- AR / consultancy operating packs.

**Build rule:** create only from artifacts repeatedly used in paid work. Do not make a speculative template catalogue.

### C3. Sanitized benchmark / methods brief

A sanitized, evidence-governed methods or benchmark artifact can generate inbound interest and support buyer conversations.

**Constraint:** all public facts stay inside claim-registry allowed-use boundaries; never expose client/prospect data or imply population findings from bounded samples.

**Revenue role:** primarily authority and demand generation; paid deeper versions only if buyers explicitly request them.

### C4. Paid office-hours / bounded expert review

A short expert session can be a hybrid entry for buyers who need judgement but are not ready for a portfolio engagement.

**Rule:** sell a bounded decision-support session with a defined artifact / follow-up note, not unlimited regulatory advice.

**Expansion trigger:** session reveals a portfolio workflow suited to a Transition Map, document review or recurring integrity support.

## Demand-resilience portfolio

Do not depend on one deadline or one service. Maintain three economic engines as hypotheses whose activation is evidence-led:

### Engine 1 — urgency cash
Verified regulatory transition / EUDAMED / certificate / SS(C)P changes can create near-term buyer urgency where a qualified buyer confirms the workflow.

Candidate entries: A1–A4.

### Engine 2 — recurring operational change
Portfolios, certificates, evidence and controlled documents continue changing after transition deadlines.

Candidate entries: A6, B1–B3.

### Engine 3 — distribution / reusable knowledge
Digital tools, samples, methods briefs and partner relationships can compound reach with low marginal cost after repeated paid-work evidence exists.

Candidate entries: C1–C4 plus B2 partner distribution.

If one engine weakens, resources may move to the others only when evidence supports the shift rather than because an alternative is available on paper.

## Cash-linked operating loops

### Loop 1 — targeted conversation → micro-scope → core pilot

`3–5 high-fit contacts → qualified workflow conversation → Portfolio Evidence Triage or small Transition Map scope → paid delivery → expansion question`

**Required learning output:** buyer response, non-response, objection or buying signal that updates the hypothesis. Revenue is desired, not promised.

### Loop 2 — pilot → refresh / change event

`first portfolio delivery → identify which evidence state will change / be revisited → offer bounded refresh when that trigger occurs → repeat delivery → managed watch if repeated`

Never manufacture urgency; use real operational triggers.

### Loop 3 — consultancy partner → portfolio desk

`qualified AR/consultancy conversation → small white-label record set → successful handoff → second manufacturer → recurring portfolio batch`

This may become a strong scale path if partner conversations demonstrate repeated downstream demand.

### Loop 4 — document QA → regulatory portfolio expansion

`Danish document integrity job → demonstrate evidence discipline → identify broader document/portfolio handoff friction → offer bounded portfolio reconciliation only if relevant`

Do not force cross-sell where no broader pain exists.

### Loop 5 — paid work → reusable asset → passive discovery

`repeated paid-delivery artifact → sanitize/generalize → productize only after repeated use → publish/sell with approval → route qualified users back to service`

Never publish buyer-specific evidence.

### Loop 6 — regulatory change → buyer reactivation

`verified material external change → map affected prior buyer workflows → evidence-safe reactivation note → bounded change review → recurring watch if valuable`

Use only verified sources and current claim governance. Do not turn every news item into outreach.

## Offer activation sequence

Do not launch all entries publicly at once.

1. Keep Class III Transition Map as the flagship and only default `DO NOW` entry.
2. Use **Portfolio Evidence Triage** only when a qualified buyer's objection is scope/commitment and the smaller scope preserves useful value.
3. Use **Identifier + Certificate Reconciliation Sprint** when that is the buyer's actual narrow pain.
4. Use **SS(C)P Operations Readiness Pack** when the buyer explicitly owns that workflow.
5. Use **Danish Market Document Integrity Review** only for confirmed localization/document-control needs.
6. Offer **Change-Event Review / Integrity Watch** only after a baseline has been delivered or a repeat need is visible.
7. Test **White-Label Portfolio Desk** selectively with qualified AR/consultancy partners; do not mass-launch it or treat partner leverage as validated demand.
8. Productize passive assets only from repeated paid artifacts.

## Commercial evidence fields

For each qualified conversation, capture privately:

- buyer type;
- trigger event;
- current manual workflow;
- frequency / recurrence;
- consequence of delay/rework;
- who owns the workflow;
- which smallest service entry fits;
- whether the buyer will supply a bounded evidence set;
- priced-scope request / budget path / pilot commitment;
- objection;
- repeat / expansion potential.

Aggregate only non-identifying commercial learning into the public repository.

---

## Decision / kill rules

### Keep / expand
A service entry earns more effort when qualified buyers pay, request priced scope, repeat it, expand it or introduce another portfolio.

### Refine
Repeated pain is confirmed but scope, packaging, proof or delivery friction blocks conversion.

### Reposition
A different role or buyer consistently owns the budget than originally expected.

### Stop
After 10 qualified conversations for an entry, if there is no concrete buying signal and the same objection repeats, stop building that entry and move resources to a stronger one.

### Automate
Only automate a workflow after the same manual step creates material friction in multiple paid deliveries.

---

## Rapid-change adaptation rule

At least monthly, and immediately after a material verified regulatory/market change, reassess each active service entry on:

- current buyer urgency;
- time-to-first-invoice;
- repeat frequency;
- delivery effort;
- gross margin potential;
- evidence/governance risk;
- dependency on one deadline;
- partner-distribution potential;
- amount of reusable tooling already available.

Move effort toward services with the best combination of **real demand + low delivery friction + repeatability + strategic learning**.

Do not defend a service because code has already been written for it.

---

## Current recommended allocation

Until real paid evidence changes it:

- **50%** buyer acquisition / conversations / follow-up;
- **25%** paid-pilot delivery readiness and delivery;
- **15%** evidence / regulatory intelligence supporting current offers;
- **10%** website, automation and product refinement driven by actual friction.

The target is not maximum activity. It is a growing number of paid, repeatable, evidence-governed workflows with enough margin to reinvest.
