# Obelis conversation brief — Class III transition work-plan thesis

Status: internal preparation asset. Calendar event not found in connected Google Calendar; do not infer timing or attendees from this file.

## Conversation objective

Test whether an authorised representative managing multiple manufacturer portfolios experiences a concrete portfolio-planning problem around legacy-to-MDR transition, certificate timing, Basic UDI-DI readiness, SS(C)P operations and market-language document control.

Do **not** lead with an allegation, audit finding, or generic EUDAMED education pitch.

## Opening hypothesis

A portfolio AR may know that transition work exists but still lack a compact, evidence-backed queue answering:

- which class III / implantable portfolio items remain on a legacy registration path;
- which certificate / transition triggers occur first;
- which items need Basic UDI-DI or identifier reconciliation;
- where SS(C)P master / translation / validation workflow needs confirmation;
- which market-language document sets create operational dependencies;
- which rows are blocked by missing evidence rather than by regulatory judgement.

## Discovery questions

1. How do you currently identify which client class III / implantable devices are still represented through legacy registration paths?
2. Is certificate / transition timing managed centrally across portfolios, or mostly within each manufacturer relationship?
3. Which fields are hardest to reconcile across EUDAMED, certificate evidence and manufacturer-controlled records?
4. When a portfolio row is incomplete, what usually blocks action: missing certificate data, identifiers, SS(C)P state, market-language information, or ownership?
5. Would a portfolio-level transition queue be useful if every machine-detected signal were separated from the human regulatory judgement needed to act on it?
6. What would make such a report useful enough to repeat across multiple manufacturers rather than treat as a one-off analysis?

## Demonstration shape

If useful, demonstrate the **structure**, not named-device allegations:

1. Intake CSV / export.
2. Structural validation and evidence-gap diagnostics.
3. MF / legacy / MDR / PR-aware segmentation.
4. Operator-priority queue based on verified timing and market relevance.
5. Evidence ledger and explicit unresolved questions.
6. Human-reviewed work plan.

Use sanitized example data unless Obelis supplies or authorises portfolio-specific data.

## Claims allowed in discussion

- Article 32 manufacturer duty-holder context — `CO-CLM-0001`.
- B-prefixed EUDAMED DI legacy identifier structure — `CO-CLM-0004`.
- ClinicOps B-prefix operational interpretation only when explicitly labelled as derivation — `CO-CLM-0005`.
- MDCG 2026-4 manufacturer-upload / notified-body indication operating model — `CO-CLM-0009`.
- MDCG recommendation for pre-mandatory-use SS(C)P upload by 27 February 2027, clearly described as non-binding — `CO-CLM-0010`.

The 8 September sample (`CO-CLM-0002`) can support methodology discussion but must not be presented as a population rate or as evidence about Obelis clients.

## Claims to avoid

- Unsupported diligence-failure allegations about SS(C)P linkage.
- Claims of complete, end-to-end EUDAMED public-register audit coverage.
- Treating a B-prefix as proof of non-compliance or as proof of a specific SS(C)P outcome.
- Presenting 27 February 2027 as a statutory MDR deadline.
- Any claim about the number or status of Obelis client devices without actual portfolio evidence.

## Pilot proposal if discovery validates the problem

**Small pilot:** one manufacturer portfolio or a deliberately limited set of class III / implantable rows.

ClinicOps supplies:
- normalized portfolio map;
- evidence-quality diagnostics;
- transition work queue;
- unresolved evidence list;
- human-reviewed action plan.

Obelis supplies, where available:
- portfolio/device list;
- certificate / transition timing;
- target markets;
- any internal identifiers needed to join public and client evidence.

## Pilot success signal

The buyer finds at least one of these valuable enough to continue:
- a row moved earlier in the work queue because of evidence-supported timing;
- an evidence gap becomes visible before it causes rework;
- a repeated manual portfolio reconciliation step can be standardized;
- the output can be reused across multiple manufacturer relationships.

## Commercial posture

The software layer should stay cheap and reproducible. The paid value is accountable interpretation, evidence reconciliation and portfolio work planning.

Do not build a larger dashboard before three real portfolio conversations validate that this workflow changes buyer decisions.
